# Cats 在沙箱市场中的位置

> **这份文档是分析，不是实现依据。** 跨组件的决定以 [`docs/decisions/`](decisions/) 的 ADR 为准，
> Cats 自己的性能数字以[实验总报告](experiments-2026-07-21-storage-lifecycle.md)及原始 CSV 为准。
>
> **写法**：前六节讲行业，不提 Cats；第七节起才谈 Cats 落在哪、最大的优点是什么、谁会付费。
>
> 竞品事实核实于 2026-07-27，取自厂商官方文档、产品 changelog 和第三方实测。
> 逐个产品的详细档案、定价原始数据和用户原话见[竞品与市场格局分析](cats-competitive-landscape.md)。

---

## 1. 这个市场在卖什么

一句话：**让 AI 写出来的代码有个地方跑，跑坏了不牵连别人。**

买的人主要有两类：

- **做 AI 产品的公司。** 他们的用户每分钟产生大量代码要执行。Manus 买 E2B，Lovable 买 Modal，
  LangChain 买 Daytona。要的是「同时能跑几万个、别崩」。
- **开发者自己。** 想要一台云上的机器，交给 agent 用，人不在的时候它继续干活。
  要的是「我回来的时候它还在」。

市场目前主要服务第一类。判断任何一个产品的位置，先看它是给哪一类人做的。

---

## 2. 第一种分法：机器能活多久

这是最重要的一条线。一个产品认为机器该活多久，决定了它其他所有部分怎么设计——
存储怎么做、账单怎么算、有没有固定网址。

| 层 | 机器能活多久 | 关掉之后剩下什么 | 谁在这一层 |
|---|---|---|---|
| **一** | 跑完就没 | 什么都不剩，结果要自己拷走 | Cloudflare、AWS Lambda、Google Cloud Run sandboxes、Azure、百度 |
| **二** | 一次会话，超时删除 | 什么都不剩 | Modal、Vercel、E2B 免费档、Runloop、腾讯、火山、阿里 |
| **三** | 可以睡，睡醒还在 | 硬盘在，有的连内存和进程也在 | E2B 付费档、Blaxel、Freestyle、Together、Daytona |
| **四** | 不设上限，有固定网址 | 硬盘在，网址不变，换一台物理机也能起来 | Fly Sprites |
| **五** | 机器和硬盘分开活 | 删掉机器，硬盘还在，可以挂到下一台上 | 几乎没有 |

时长上限的具体数字，能看出这条线卡在哪里：

| 上限 | 产品 |
|---|---|
| 300 秒 | 百度 |
| 1 小时 | PPIO、E2B 免费档 |
| 8 小时 | AWS AgentCore、AWS Lambda MicroVMs |
| **24 小时** | **E2B、Vercel、Modal、腾讯、火山——这是行业默认天花板** |
| 48 小时 | Runloop |
| 不设上限 | Fly Sprites、Fly Machines、Northflank、Daytona |

三个观察：

**第三层最挤。** 2026 年大部分产品都在这里，能力差不多：能暂停、能唤醒、暂停时不收计算费。
在这一层里比，比的是唤醒快多少毫秒。

**第四层只有一家在对外卖。** Fly Sprites。另外两个做到这一层的——Perplexity 的 SPACE、
Cognition 的 Devin——都是自己用，不卖。

**第五层的意思**是：一台机器和它的硬盘是两样东西，可以分开管。换机器的时候数据不用搬。
这在传统云服务上是常识（云服务器和云硬盘就是分开的），但沙箱市场很少这么做。为什么，见第四节。

---

## 3. 第二种分法：隔离用什么技术——已经不是区别了

四种做法：浏览器里的 WASM、共享内核的容器、用户态内核（gVisor）、独立的小虚拟机。

**29 个产品里 19 个用小虚拟机。** 这一项现在是入场券，不是卖点。

门槛也已经被开源清掉了。腾讯的 CubeSandbox 和阿里的 OpenSandbox 都开源了，加起来两万多个 star，
冷启动 60 毫秒，快照、挂起、唤醒都有，还带一键部署。两年前「能做出 60 毫秒的小虚拟机」是壁垒，
现在是下载下来就能用。

剩下两条路各有硬伤：**共享内核的容器**（Daytona 默认档、Sealos、Codespaces）有完整的 Linux，
但内核和宿主机共用，不敢跑完全不可信的代码；**gVisor**（Modal 默认档）挂不了块设备文件系统，
部分程序会悄悄失效，还会把内核版本报成 4.4.0。

---

## 4. 第三种分法：产品是从哪一类老产品改过来的

这条线最能解释一个产品为什么有某些能力、为什么缺某些能力。

**从函数计算改的**——Vercel、Cloudflare、Modal、阿里云函数、百度函数。
本来的用途是「收到一个请求，跑一段代码，返回结果」。它们默认认为代码跑完就该结束，
所以「能保存状态」是后来加的功能。明显的痕迹：这几家都按调用次数收费，
而这种收法对「长期存在、偶尔被访问的机器」是反的——访问越少，每次越贵。

**从云端 IDE 改的**——Daytona、Coder、Ona、GitHub Codespaces、Sealos。
本来是给人在浏览器里写代码用的。它们默认认为工作区要一直在，保存状态是自带的。
但它们本来不需要防着用户，所以隔离是后补的，好几家到现在还是共享内核。

**从虚拟机改的**——Fly Machines、Fly Sprites。
本来就是租一台机器给你。开机关机、挂硬盘、绑地址，都是现成的概念。

**第五层为什么空着，答案在这里：机器和硬盘分开管，是虚拟机世界的常识，
而这个市场大部分玩家来自函数计算世界，那个世界里没有硬盘这个东西。**

Fly Sprites 是唯一从虚拟机那条线改过来做 agent 的，所以它做到了第四层。
但它为了让产品简单，把硬盘并回了机器里：删掉一个 Sprite，它的快照一起删掉；
官方文档里搜不到 volume 这个词。想换个系统镜像，官方给的办法是删了重建，再自己把文件拷过去。

云端 IDE 那条线正在被收编。OpenAI 在 2026 年 6 月 11 日买下 Ona（原来的 Gitpod），
用来给 Codex 提供能跑几小时到几天的云端环境，卖点之一是装在客户自己的云里。
Coder 在 5 月发了自己的 agent 产品，主打企业自己部署。

> 这一节是给工程师看的分法。同一件事怎么说给客户听，见 7.1。

## 5. 这个行业的钱在哪里

目前唯一公开的硬数字：**Modal 年收入超过 3 亿美元，沙箱业务占三分之一以上。**
它服务的是 Lovable 这类客户——48 小时创建 25 万个应用，峰值同时 2 万个沙箱。

也就是说：**这个行业现在赚到的钱，来自「同时跑很多个短任务」，不是来自「长期养着几台机器」。**

反过来看「长期养着机器」：厂商都在做这个功能（Vercel 说「保存状态是默认行为」，
E2B 的暂停不限时长，Anthropic 说自己的沙箱「设计上就是有状态的」），
**但到现在找不到一个公开的客户案例，是愿意为「能长期存在」单独付钱的。**

这件事必须先摆在桌面上，再谈定位。第 11 节会给出一个解释：这有一部分是价格造成的，
不一定是需求不存在。

## 6. 行业普遍没解决的三件事

**一、账单看不懂。**
Fly Sprites 发布帖下面票数最高的两个问题是「我花了多少钱」和「我的机器为什么没有自动睡觉」。
到现在没有厂商在产品里回答这两个问题。
大部分产品按你申请的规格收费，不按你实际用掉的收。Vercel 的文档写得直白：
内存按申请的数量乘以运行时长收，机器闲着也照收。一台 4GB 的机器什么都不干，一个月 61 美元。

**二、长期存在的机器，和它的数据怎么分开。**
就是第五层。市面上有独立硬盘的几家，硬盘大多是挂对象存储的目录，
没有原子改名、不是事务性的、两边同时写就看谁最后写——git、SQLite、node_modules
这三类最常见的负载在上面表现不对或者很慢。

**三、agent 往外发请求怎么管。**
只有 Cloudflare 认真做了：按域名做白名单，默认禁止一切外发；凭据由平台注入，沙箱里看不到明文；
HTTPS 用每个沙箱一张临时证书做拦截。
Figma、Anthropic、Cognition 选 Cloudflare，很可能就是买这个——Cognition 自己有完整的快照能力，
不需要 Cloudflare 的持久化。

## 7. Cats 落在哪一层

| 按哪条线看 | Cats 在哪 | 说明 |
|---|---|---|
| 能活多久 | **第五层** | Cat 是机器，Disk 是硬盘，两样东西分开管。可以单独建一块盘、挂到一台机器上、卸下来、挂到另一台上；删掉机器，盘还在。快照挂在盘上而不是机器上，所以删掉机器不会把快照一起删掉。代码里 `DiskState::Available` 就是「这块盘现在没挂在任何机器上，但它活着」这个状态 |
| 隔离技术 | 小虚拟机 | 和大多数一样。**这一项不构成区别** |
| 从哪改的 | **虚拟机那条** | 产品结构就是「云服务器 + 云硬盘 + 固定地址 + 开机关机」那一套，搬到 agent 的场景上 |

### 7.1 怎么把这件事说给客户听：不是「手和大脑」，是「动作」和「场所」

第 4 节那套「从哪一类老产品改过来」是给工程师看的。同一件事对客户要换个说法。

**一个常见但站不住的说法是「别人跑的是 agent 的手和眼，我们跑的是大脑」。**
问题在于：不管哪家沙箱，模型调用都是往外发的。E2B、Modal、Vercel 里跑的是「调用模型的那段循环」，
不是模型本身；就算把 agent 进程也放进虚拟机（Devin 那种），思考仍然发生在远端 API。
客户听到这句的第一反应会是「我的模型又不在你那儿跑」，然后后面真正成立的部分就被挡住了。

**但这个说法指向的东西是真的。** 换个角度：模型是无状态的，同一个模型谁调都一样。
那么一个 agent 凭什么是「这一个」而不是另一个？靠它积累下来的东西——装过的依赖、
改了一半的工作树、当前在哪个分支、还没关的服务、试错留下的痕迹。**这些全在盘上。**

所以盒子里装的不是 agent 的思考，是**它的记忆和没干完的活**。删掉盒子，agent 不是变笨了，
是失忆了，得从头再来一遍。

准确的对比是这样：

| | 大部分沙箱 | Cats |
|---|---|---|
| 它是什么 | 一次**动作** | 一个**场所** |
| 怎么用 | 调用一次，做一件事，拿结果 | 有名字、有地址、有自己的盘 |
| 有没有归属 | 没有。这次和上次没关系 | 有。同一个用户回来还是那个地方 |
| 结束之后 | 什么都不剩 | 东西都还在原地 |

这个说法有两个好处。**一是它躲开了「模型在哪跑」的争论**，直接落在客户能自己验证的事实上：
关掉再回来，东西还在不在。

**二是它能解释一件本来看着奇怪的事——计费方式。**
卖动作就按次数收费，卖场所就按时间和面积收租。回头看第 4 节：
Vercel、Cloudflare、阿里云函数、百度函数**都收调用次数费**，而 Cats 和 Sprites 都不收。
这不是巧合，这几家骨子里认为自己卖的是动作。
**一个说法能预测出观察到的定价差异，说明它抓到的是真东西，不只是修辞。**

**但把 Sprites 和 Cats 放在同一格，只对到这一层为止。** 再往下问一句就分开了——
**这个场所能不能搬家？** Sprites 的盘是机器的一部分，删掉机器快照跟着删，换基础镜像要删了重建
再自己拷文件。它是个场所，但是**搬不了家的场所**：换房子就得扔家具。Cats 的盘独立于机器。

所以完整的说法是三段，能收钱的是第三段，前两段是让客户听懂第三段的铺垫：

1. 大部分沙箱是**一次动作**——跑段脚本、查个网页，做完就散。
2. Cats 和 Sprites 是**一个场所**——有名字、有地址、有自己的盘，agent 的记忆和没干完的活存在这儿。
3. 而在这一类里，**Cats 是能搬家的那个**——盘的命比机器长（见 7.3 与 11.6）。

### 7.2 「关机」在 Cats 这里分四种，不是一种

| 状态 | 保留什么 | 释放什么 | 醒来要多久 |
|---|---|---|---|
| **Running** | 全部 | 无 | —— |
| **Suspended** | 进程状态 | CPU；内存换到本地盘 | 0.21 秒 |
| **Warm** | 进程状态 | CPU 和内存都不占了，虚拟机进程退出 | 0.38 秒 |
| **Cold** | 只剩远端硬盘 | 本机上什么都不留，任何一台机器都能把它拉起来 | 1.755 秒 |

（实验室数字，AWS 裸金属、本地 NVMe、小样本中位数，不是服务承诺。）

Warm 是别人没有的那一档：**不占内存，但进程还在。**
Fly Sprites 只有三档，它想省掉常驻内存就必须把进程状态丢掉。

### 7.3 但「第五层」这三个字要说全

单说「有独立硬盘」或者「能睡」，都已经有人做到了。Cats 站得住的是三件事同时成立：

| 要求 | 谁做到了 | 谁没有 |
|---|---|---|
| **硬盘不随机器消亡** | Cats、Vercel Drives、Modal、Daytona、Fly Machines | Fly Sprites、Cloudflare |
| **硬盘是真硬盘**（标准块设备加没改过的 ext4，不是挂对象存储的目录） | Cats、Fly Machines | Vercel Drives（官方写的是「挂在沙箱上的一个目录」）、Daytona、Modal、Cloudflare |
| **能记住内存和进程，还能换一台物理机恢复** | Cats、Fly Sprites、Perplexity SPACE（不卖） | Vercel（只记硬盘，恢复后要自己重启进程）、Cloudflare（硬盘不保留）、Fly Machines（硬盘绑死在一台物理机上） |

三条都占的，目前只有 Cats。**但对外必须三条一起说**——只说其中一条，随时会被别人的一次更新抹平。

一个例子说明为什么要这么小心：Vercel 的 Drives 在 2026 年 6 月已经是「生命周期独立于沙箱」的硬盘了，
官方写着「手动删除之前一直在」。第一条已经不是 Cats 独有。
但同一张官方对比表里，Drive 的性能写的是「写入和命中缓存的读取是 NVMe 速度，**没命中缓存的读取会慢**」，
而快照那一列写的是「读写都是 NVMe 速度」——这说明 Drive 是本地缓存加远端主存，不是一块真硬盘。
官方也建议「私有测试期间只用来做缓存，不要放生产数据」。

## 8. 最大的优点：关机不是损失

市面上每一家，关掉机器都要付出一样代价——**要么丢东西，要么继续掏钱**：

| 产品 | 关掉之后 |
|---|---|
| Vercel | 状态留着，但内存按申请的规格乘全时长收，闲着照收。4GB 的机器什么都不干，一个月 61 美元 |
| Cloudflare | 不收钱，但磁盘清空，下次是全新的 |
| E2B、Blaxel 这一档 | 暂停不收计算费，但盘跟着沙箱走，沙箱没了盘就没了 |
| Fly Sprites | 前两条都躲开了，但睡久了必然掉到 Cold——内存丢掉、进程重启；而且盘是 sprite 的一部分，删机器等于删数据 |
| **Cats** | **不花钱、不丢进程、盘还独立活着** |

**这条比其他优点大，是因为它改变的是用户的行为，不只是一个更好的数字。**
冷启动从 500 毫秒降到 200 毫秒，用户的用法不变；而「关掉不吃亏」会让用户不再管生命周期这件事——
不用想什么时候该销毁、不用把状态往外倒、不用写 `onResume` 重建现场。
别的优点是参数更好，这条是一类操心事直接消失。

### 8.1 但最难被抄走的是另一条：按实际用量收费

这两件事是一件事的两面。**「能休眠」只有在休眠真的不花钱时才成立**，
而休眠花不花钱取决于计费方式，不取决于技术。

这一条特殊在：**别人不是做不到，是不会做。**
Cats 其他所有优点，对手要么还没做、要么技术上受限——前者会被补上，后者会被绕开。
只有计费这条，挡在对手面前的是他们自己的收入。

**技术上最大的优点是「关机不是损失」，能守最久的是「按实际用量收费」，
而后者是前者能成立的前提。**

### 8.2 按「别人要追上来得改什么」排序

改代码容易，改收入结构难。

| 排 | 差异 | 别人要追上来得改什么 | 判断 |
|---|---|---|---|
| **1** | **按实际用量收费**（CPU 按累计时间，内存按实际占用的时间积分。申请 4GB 只用了 1GB，就按 1GB 收） | 改的不是代码，是自己的收入结构。Vercel 满载时一个机位卖 0.34 美元，自己买机器的成本是 0.064 美元，中间的差价有一大半来自「内存按申请量收，闲着也收」 | **技术上一周能改完，商业上不会改。这种差异最难被抹平** |
| **2** | **机器和硬盘分开** | 要改产品的基本结构：接口要改、计费要改、用户理解产品的方式也要改。Fly Sprites 做这件事等于重做一遍产品 | 最难追，也最容易演示给人看 |
| **3** | **Warm 这一档**（不占内存但进程还在） | 要换虚拟机管理程序。用 Firecracker 的那几家（E2B、Vercel、Fly、Sprites）还撞上一条硬限制：Firecracker 从 1.6.0 起，**自定义硬盘后端和虚拟机快照只能二选一**，官方文档写明前者禁止用于生产 | 难，而且目前没有竞品公开讨论过这个岔路口 |
| 4 | **让程序自己说「我在忙」**（平台入口和用户程序都能持有一个工作租约，清零才睡；平台不去猜） | 改接口，不难 | 容易追，但没人做——做了等于承认「多久没动静就睡」这个猜法不对 |
| 5 | **出错时不会悄悄弄坏数据**（崩溃注入测试、旧机器写入被拒绝的测试、清空本地缓存后换机器恢复的测试） | 别人做得到，只是没公开 | 追平成本中等，但**客户看不见**——除非出事 |
| 6 | **真的 root、没改过的 ext4、独立内核** | 走 gVisor 那条路（Modal 默认）做不到，gVisor 挂不了块设备文件系统。用 Firecracker 的做得到 | 是入场券，不是区别 |
| 7 | **可以装在自己机房里** | 在沙箱产品里是独一份 | 但按「一台机器」来定位，对面就是 Coder 和 Ona，**它们本来就干这个** |

前三条有个共同点：**都不是「我们也能做」，而是「别人做了会伤到自己」。**

### 8.3 第 1 条值得算一笔账

2 核 4GB 的机器，CPU 用了一成，实际占内存 1GB，跑一小时：

| 产品 | 怎么收 | 一小时 |
|---|---|---|
| E2B | 按申请的规格全收 | $0.1656 |
| Vercel | CPU 按实际，内存按申请量乘全时长 | $0.1104 |
| **Cats** | **CPU 和内存都按实际** | **$0.0590** |

**Cats 的标价是三家里最高的**（每 CPU 小时 $0.07、每 GiB 小时 $0.045），**实际账单是最低的。**
这件事现在没有出现在任何对外材料里。

## 9. 这个位置缺什么

已经有的东西有个共同点：**都是把「一台机器」做深**——四种关机状态、硬盘独立于机器、
出错时不弄坏数据、按实际用量收费、让程序自己说在不在忙、固定网址被访问就醒。

缺的东西也有共同点：**都是「很多台机器」的事**——

- 不能从一台机器复制出很多台（没有 fork）
- 没有预装好的模板和预热池
- 没有现成可用的镜像
- 单个节点上的并发唤醒有排队和限额了，但整个集群层面的配额和限速没做，对外也没有能公布的并发数字
- 一块盘只能挂一台机器，多台机器读同一份数据做不了

而第 5 节说过，这个行业现在赚到的钱在「很多台」那边。
**这不是「还没排上」，是「把一台机器做深」这个选择的另一面。**

还有一条要单独说：**Cats 的价目表里，存储那一项是空的。**
代码里注册了热存储和冷存储两个计量项，但没填价格。
而「关机之后盘还在」正是 Cats 的主要卖点——这部分的收入现在没有。

> 第 11 节选定目标客户之后，这份清单里有几条的紧急程度会变——有些不必做，有些要提前。

## 10. 谁会为此付费

先说一件不舒服的事：**到现在为止，找不到一个公开案例是为「能长期存在」单独付钱的。**
厂商都在做这个功能，但没人证明有人愿意为它多掏钱。所以下面按证据强度排，不按「应该」排。

### 10.1 第一类：agent 要等外部事情发生。证据最硬

agent 提交了 PR，要等 CI 跑 20 分钟；等人 review 两天；等审批。
这段时间机器必须活着——上下文、依赖、改到一半的工作树都在里面——但什么都不干。

Cognition 为 Devin 自己造了 hypervisor 级快照，花了一年多，
官方说法就是「CI 结果或 review 评论到来时原地恢复」。
**有人已经用自建行为证明这件事值钱了。**

算一笔账：2 核 4GB，一个任务跨 8 小时，真正在算的只有半小时。

| 计费方式 | 8 小时合计 |
|---|---|
| 按预留收（E2B 口径 $0.1656/机时） | **$1.32** |
| Cats（CPU 按实际约 $0.07，中间七小时在 Warm、内存几乎不计） | **约 $0.12** |

**差一个数量级。** 而且这不是极端假设——「等待时间远长于计算时间」是异步 agent 的常态。

### 10.2 第二类：每个用户一台长驻机器的产品

不是「每个任务开一个沙箱」，是「每个用户有一台自己的机器」：
给每个客户一个数据分析工作区、给每个研究员一个长期实验环境、给每个项目一台不会重置的开发机。

这类产品的形状是：**机器数等于用户数，但同时活跃的可能只有百分之几。**
按预留计费的话，剩下 95% 全在烧钱。这是 Cats 的经济模型最贴合的形状。

**这一类已选定为目标客户，详见第 11 节。**

### 10.3 第三类：吃真硬盘语义的负载

git 仓库、SQLite、node_modules。这三样在挂对象存储的目录上要么行为不对、要么很慢——
没有原子改名、不是事务性的。市面上大多数「独立硬盘」都是这种目录挂载。
要跑这些又要长期保留的，选择很少。

这一类更像是**别人被淘汰出局，剩下 Cats**，不是 Cats 主动赢——
但它最容易做成演示：同一个仓库，在别家上 `git status` 慢或者出错，在 Cats 上和本机一样。

### 10.4 谁不会付费

- **头部大客户。** 长期挂着超过一千台机器就该自己搭了，Cursor、Cognition、Perplexity 都是这么做的。
- **跑短任务要并发的。** 这是 Modal 和 E2B 的地盘，也是这个行业目前真正赚到钱的地方。
  Cats 现在缺的正好是这一块。
- **只想便宜一点的。** 单看标价 Cats 是最贵的，省钱要在低利用率下才成立。

### 10.5 一句话提醒

**没有人会为「持久化」付钱，但会为「账单降了一个数量级」付钱。**

这是同一件事的两种说法，但只有后者能卖。
现在产品站上「状态比进程活得久」是第一条推论，而「按实际用量收费」排在第五条——应该反过来。

而且有个连带的活儿躲不掉：**按实际用量收费的账单没法提前估。**
别家的客户能自己乘一乘算出来，Cats 的客户不能。
所以「能看懂自己花了多少钱」对 Cats 不是加分项，是卖这个优点的前置条件。

## 11. 目标客户：每个用户一台长驻机器的产品

选这一类，理由不是「这块市场更大」，而是**它同时躲开了两个陷阱**。

### 11.1 躲开了「客户越成功越自建」

算一个一万用户、每人一个 10 GiB 工作区、同时活跃 3%（300 台）的产品：

| | 每月 |
|---|---|
| 全部按预留计费常驻（E2B 口径） | 约 **120 万美元**——这类产品今天根本做不了长驻 |
| Cats：300 台活跃 × $0.059/机时 | 约 **1.3 万美元** |
| Cats：9,700 台休眠的计算费 | 约 **0** |
| 存储 10 万 GiB，按冷存储 $0.02/GB·月 | 约 **2,000 美元** |
| **合计** | **约 1.5 万美元** |

这个客户一年付 18 万美元。而他自建要三个基础设施工程师，一年 90 万——
**是他账单的五倍，永远回不了本。**

对比第 10.4 节那条警告：那条算的是高并发计算型客户，他们的账单里全是算力，
而算力有 2.6 倍加价可省，所以到一千台就该自己搭。
**这类客户的账单主要是存储，存储没有那么大的加价空间可赚，自建的动机就没了。**

顺带一个推论，它也解释了第 5 节那个「找不到人为持久化付钱」的现象：
**市场看起来都在做「一次任务」，有一部分原因是长驻在现行计费下付不起。
需求是被价格压掉的，不一定是不存在。**

### 11.2 躲开了「宽度是空的」

每个用户一台机器，不需要从一台复制出很多台（不需要 fork）、不需要峰值两万并发、
不需要百毫秒冷启动——用户打开自己的工作区，等一两秒是正常的。

**第 9 节列的那些缺口，这个客户群基本不需要。** 这是选它最实际的一个理由。

### 11.3 存储费率从第二优先级变成第一

看 11.1 那张表：97% 的机器在睡觉，**存储就是价格本身，算力反而是零头。**

而热冷两档的差距在这个规模上是决定性的：

| 费率 | 10 万 GiB 每月 |
|---|---|
| 冷存储 $0.02/GB·月 | **2,000 美元** |
| 热存储 $0.50/GB·月 | **50,000 美元**——比算力还贵四倍，成本优势没了 |

**热冷两档不是定价上的讲究，是这门生意能不能成立的分界线。**

### 11.4 有一个前提今天还没满足：跨机器不去重

这是选定这个方向之后暴露出来的、最要紧的一条技术缺口。当前代码的事实：

- 新机器创建时，基础镜像是**整份流进新卷**的
  （`node-agent/src/ch.rs` 的 `seed_volume`，注释写着 "Golden-root seeding: stream a raw image into a fresh volume"）
- 提交时数据对象的键是 `volumes/<卷 id>/data/<object-id>`（`api/src/chunk.rs`）
- 而 `object-id` 由**事务号加 chunk 序号**生成（`data_object_id(txn, chunk_idx) = "{txn}-c{chunk_idx}"`），
  **不是内容哈希**

也就是说：**一万个用户从同一个基础镜像开出来，对象存储里就是一万份完整副本。**
11.1 里那 10 万 GiB 就是这么来的。

如果跨卷共享，基础镜像存一份，加上每人的增量——假设人均增量 1 GiB，
存储从 10 万 GiB 降到约 1 万 GiB，**账单从 2,000 降到 200 美元。**

改造的难度要说清楚，不要低估：

- sha256 已经算了，但它存在映射表里**做完整性校验，不做寻址**
- map 节点已经是内容寻址（`maps/<hex-sha256>.node`），所以这个模式在代码库里有先例
- 但数据对象改成内容寻址，会动到提交协议的幂等性——
  现在用事务号派生键，换来的是「同一个事务重放会写到同一个键」这个性质
- 还要加跨卷的引用计数或者标记清扫，共享之后回收变难
- `blockd` 协议是 Frozen v1，改键布局要新开 ADR

**动手之前先测一个数：从同一个基础镜像派生 N 个工作区、各自装点东西之后，
实际重合的 chunk 有多少。** 这个数决定了跨卷去重值不值得做，
也决定了 11.1 的成本模型是那个样子还是要打折。**这比继续优化冷启动重要。**

### 11.5 对手换人了

选了这个方向，E2B、Modal、Vercel 基本不在牌桌上——
**不是它们不想做，是它们的计费方式把自己挡在门外了。**
按预留收费的产品做不了「一万台机器 97% 在睡觉」这个形状。
Cloudflare 更直接：磁盘不保留，压根做不了每人一个工作区。

真正的对手剩两家：

| 对手 | 情况 |
|---|---|
| **Fly Sprites** | 官方说法就是「给 agent 用的持久 Linux 机器」，冷存储也是 $0.02/GB·月。正面对手 |
| **Daytona 的 Archived 状态** | 盘搬到对象存储、完全不计费。但天花板只有 4 核 8G、默认共享内核，而且 2026 年 6 月闭源 |

对手从五六家变成两家，而且都是能打的仗。

### 11.6 对 Sprites 最锋利的一句话：换基础镜像

这个客户群一定会遇到：一万个用户的工作区都从 v3 镜像开出来，现在要升到 v4。

**Sprites 官方给的办法是删掉重建，然后自己把文件拷回去。对一万个用户做这件事是场事故。**
而 Cats 的盘独立于机器，换镜像就是换机器不换盘。

「盘独立于机器」原本只是最容易演示的一条。选定这个客户群之后，
**它变成了这个客户每年都会撞上一次的具体麻烦。**

### 11.7 这个选择的两个风险

**客户集中。** 平台型客户是少数几个大单，不是很多小单。签一个要谈很久，丢一个伤很重。
前期至少要同时推进三四个，不能押一个。

**这个市场仍然没有被证明。** 11.1 的账能算通，不等于有人已经在这么花钱。
**建议尽早找一个真实客户把这笔账当面算一遍**——
如果他看完不动心，说明这套推理里有一环是错的，越早知道越好。

## 12. 要做的事

按第 11 节选定的目标客户排序。**顺序和没选目标之前不一样。**

### 12.1 必须做

1. **测出同一基础镜像派生多个工作区之后的 chunk 重合率**（服务 11.4）。
   这个数决定成本模型成不成立，也决定第 2 条怎么定价。**先做这个，它最便宜也最要紧。**
2. **把存储价格填上，分热和冷两档**（服务 11.3）。
   对目标客户，存储就是价格本身。
   Fly Sprites 是被社区抱怨「睡着的机器还按每月每 GB 0.5 美元收」之后才加的两档结构，答案是现成的。
3. **跨卷去重**（服务 11.4）。视第 1 条的结果决定投入。要新开 ADR，
   注意提交协议的幂等性和共享对象的回收。
4. **把「按实际用量收费」和「账单能看懂」做成用户看得见的东西**（服务 8.1、10.5）。
   这是最难被抹平的一条，现在对外一个字都没提。
   而且按实际用量收费的账单更难提前估，所以账单可视化不是加分项，是必需品。
   采样和记账的链路已经有了。
5. **测出一个真实的冷启动数字**（服务 7.3 第三条）。
   现在的两个数字是两条路径：1.755 秒是本地 NVMe 上优化过的启动路径，
   39.868 秒是从 S3 拉数据的 Python 原型。真实生产情况两者都不是。

### 12.2 目标客户直接要的

6. **基础镜像的版本和升级路径**（服务 11.6）。
   一万个工作区从 v3 迁到 v4，要有 API，不能靠客户自己写脚本。
7. **批量操作接口**：批量创建、批量休眠、批量迁移。
   注意这和「高并发」不是一回事，容易得多。
8. **一个节点能挂多少台休眠机器**——这是目标客户真正拿来比价的数字，现在没人公布。
9. **原生 vhost-user-blk 真机验收**——也是 Warm 恢复时块设备状态对齐的前提。

### 12.3 往后放

- **fork / branch** —— 每个用户一台机器，不需要分叉。
- **万级并发和集群限流** —— 活跃是散开的，不是尖峰。仍然要做，但不紧急。
- **只读共享（RO-many）** —— 基础镜像加去重能覆盖大部分「共享同一份数据」的需求。
  如果要做，作为新 ADR，不要悄悄放宽现有的「同时只能一个写入方」这条约束。
- **出网管控和凭据注入** —— 学 Cloudflare，与定位不冲突，但不是目标客户的第一诉求。

### 12.4 明确不做

- **不跟人比谁更便宜、谁能同时跑更多。** 那是另一条路上的比法。
- **不做多台机器同时读写一块盘。**
- **不追冷启动毫秒数。** 厂商都把它当头条，但在用户抱怨里它排第七，
  而且目标客户打开自己的工作区，等一两秒是正常的。
- **不拿「我们也会做 microVM」当卖点。** 这一项 2026 年已经不值钱了。

## 13. 什么情况说明这个判断错了

如果下面任何一条发生，这份文档的结论要重写，不是打补丁。

**关于定位（第 7、8 节）：**

| 信号 | 说明什么 | 现在的情况 |
|---|---|---|
| Vercel Drives 正式发布，去掉「只当缓存用」的建议，并且支持保留内存和进程 | 7.3 那三条同时成立的说法被打破 | 私有测试，是目录不是硬盘，官方建议只做缓存 |
| Cloudflare 的原生整盘快照上线，并且容器和它的持久对象跑在同一处 | 第 4 节对 Cloudflare 的判断失效 | 到 2026-07-01 的 changelog 为止未上线，现在用的还是目录级备份 |
| Fly Sprites 加上独立硬盘 | 最像的对手补上了唯一明显的缺口，11.6 那句话失效 | 官方文档搜不到 volume，也没有路线图 |
| 任何一家头部厂商改成按实际用量收内存 | 8.2 第 1 条消失 | 没人这么做，那是它们的利润来源 |
| Firecracker 解禁自定义硬盘后端并支持快照 | 8.2 第 3 条的理由失效 | 仍是开发者预览版、禁止用于生产、不支持快照 |

**关于目标客户（第 11 节）：**

| 信号 | 说明什么 | 现在的情况 |
|---|---|---|
| **实测的 chunk 重合率很低**（用户各自装的东西差异大） | 11.1 的成本模型要打折，存储费率必须按不去重定 | **未测。这是第 12 节的第 1 件事** |
| 找不到一个客户愿意坐下来把 11.1 那笔账算完 | 这个客户群不成立，或者痛点没到掏钱的程度 | 未验证 |
| Fly Sprites 开始认真做平台型客户 | 正面对手，而且它有 Fly 的基础设施和品牌 | Fly 自己说 Sprites 面向个人和探索性用途，不做横向扩展 |
| OpenAI 或 Anthropic 把持久环境做成模型订阅的附赠 | 这类产品被捆绑掉，不是被竞争打掉 | Anthropic 的沙箱每小时 0.05 美元，和联网搜索一起用时免费；OpenAI 已经买下 Ona |
| Coder 或 Ona 做出真硬盘加内存级休眠的自部署版本 | 企业自部署这条路被堵 | 两家都是从云端 IDE 改过来的，隔离是后补的 |

- **Cats 的性能数字全部来自实验环境，不是服务承诺**，而且测量条件互不相同、不能互换：
  Suspended 0.213 秒、Warm 0.382 秒、优化后的 Cold 1.755 秒，都是 AWS 裸金属本地 NVMe；
  Warm 在 EBS 上是 1.090 秒；从 S3 拉数据的原型冷启动 39.868 秒。都是小样本中位数。
  测量条件见[实验总报告](experiments-2026-07-21-storage-lifecycle.md) §2、§3、§12。
- **第 11.1 节的成本测算是单点估算，不是报价。** 它假设一万用户、每人 10 GiB、活跃率 3%、
  常驻集 1 GiB、冷存储 $0.02/GB·月。这些假设里任何一个变动都会显著改变结论，
  尤其是**重合率这一项目前完全没有实测**（11.4）。
