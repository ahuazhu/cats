推论一

## 状态必须比进程活得久。

如果你要回得来，那么关掉它就不能等于失去它——装过的依赖、改到一半的工作树、还没关的服务，都得还在原地。这条推论决定了整个存储层：对象存储保存真相，本地盘只是缓存，而承诺必须是可以被测试的。

✓

**成功的 FLUSH 扛得住 Host 永久丢失**

这是一句可测试的承诺，不是形容词。它是我们所有崩溃恢复测试的判据。

✓

**本地 NVMe 是可以删掉的缓存**

删光本地缓存后，磁盘仍能按读请求从远端逐块恢复，文件树逐字节一致。

✓

**只提交变化的部分**

写几个文件不会上传整块虚拟盘。引擎只提交发生变化的逻辑 Chunk。

✓

**PersistentDisk 的生命周期独立于 Cat**

换镜像、换规格、甚至删掉这只 Cat，数据都留在原地，随时挂到下一只上——不需要销毁重建再手动拷贝。

推论二

## 那它就得是一台真机器。

「像 VM 的容器」在演示里没问题，在真实工作负载里会漏。我们的边界画在硬件虚拟化上，而不是画在措辞上。

⌁

### 独立内核，真 root

KVM + Cloud Hypervisor，每只 Cat 一个自己的 Linux 内核。`apt install` 直接用，不需要 rootless 变通。

▱

### 未修改的 ext4

Guest 看到的是标准 virtio 块设备，不是对象存储的 FUSE 挂载。所以 git、SQLite、node\_modules 的行为与你本机一致——包括原子 rename。

⊘

### Guest 拿不到平台凭据

对象存储、元数据库与租约全部是平台内部实现。Guest 里跑什么代码都够不到它们。

推论三

## 停机不是一件事，是四件。

一个笼统的「sleep」会把三种完全不同的取舍藏起来。我们把它们摊开：每一态明确说明保留了什么、释放了什么、以及还绑不绑在原来那台 Host 上。

1

### Running

vCPU 正在执行、内存驻留，磁盘持续发布持久 generation，Endpoint 可以服务流量。

完整计算资源

2

### Suspended

vCPU 暂停、Guest 内存回收到本地 backing，进程状态原样保留。换取最短的恢复路径。

保留进程状态

3

### Warm

本地快照落盘后 VMM 退出，专属运行时 RSS 归零，进程状态仍在。用一点唤醒时间换掉常驻内存。

零驻留，仍保进程

4

### Cold

释放全部 Host 本地依赖，只剩远端磁盘与控制面记录。任何一台健康 Host 都能把它拉起来。

不再绑定 Host

四态单向降级，唤醒总是回到 Running。还有一条硬规则：**任何快速恢复失败都必须收敛到一次干净的 Cold 启动**——不允许卡在中间态。慢一点可以接受，说不清自己在哪个状态不行。

推论四

## 平台不该猜你在不在忙。

行业惯例是拿 idle 计时器、CPU 阈值或网络静默去猜——猜错就是把正在跑的活睡掉，或者为无人使用的环境一直付钱。我们把判断权交还给你的程序。

✓

**没有 idle\_timeout，没有 CPU 阈值**

Cat 不是「闲了一段时间才睡」，而是在**已知没有工作之后立刻**尝试休眠。

✓

**工作是一个显式、可仲裁的信号**

平台入口（HTTP、exec、shell）自动持有工作租约；你的程序也可以自己持有。租约归零才睡。

✓

**Guest Agent 不替你判断**

它不扫 `/proc`、不看 load、不猜进程名。要长跑的后台任务，接一下租约或者显式关掉自动休眠即可。

✓

**被访问就醒**

每只 Cat 有固定的 `*.cats.run` 地址，绑名字不绑 Host。请求打进来会把它唤醒，你不需要先调一次 API。

推论五

## 为用掉的东西付费，不是为申请的规格。

如果账单按「你申请了多少」算，那么「可以休眠」就只是一句话术——空闲的机器照样烧钱。所以计量基准必须是实测。

◷

### CPU 与内存都按实测

CPU 取 cgroup 累计时间，内存取 `memory.current` 的时间积分。配了 4 GiB 但常驻集只有 1 GiB，就按 1 GiB 计费。

∅

### 不收请求费

没有按调用次数计费这一项。一台长期存在、偶尔被访问的机器，不该因为访问稀疏而每次更贵。

◔

### 休眠态几乎不产生计算费用

Warm 态专属运行时 RSS 为零。这是让「可以休眠」真正省钱、而不只是一个状态名的前提。

推论六

## 先证明正确，再谈快。

存储和生命周期出错往往是静默的——你不会立刻发现，只会在某天发现数据不对。所以我们的顺序是先把语义钉死、留下可复现的判据，再去优化路径。

✓

**旧写者 fail closed**

每个 Attachment 带 fencing epoch。网络分区后回来的旧 Host 无法覆盖新写者——这条有崩溃注入测试，不是设计意图。

✓

**换一条数据路径，不换一套语义**

块前端只做协议适配：无论走哪条路径，提交协议、dirty 追踪、租约与崩溃恢复完全一致，共用同一套正确性测试。

✓

**唤醒风暴排队，不雪崩**

并发唤醒受节点预算约束，按需要回读的内存字节数计量。超出的唤醒排队等待，而不是被拒绝后退化成完整冷启动。

✓

**我们公布测量边界**

文档里的每个性能数字都带样本数、硬件与测量口径。原型上测到的数不会被写成生产承诺——你可以自己判断它适不适用于你的负载。
